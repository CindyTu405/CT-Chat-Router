刪除對話與外鍵

資料列互相引用時，要怎麼一次刪乾淨，而且失敗時什麼都不會被改。

1問題

對話裡只要有錨定的分支，刪除就會回 500，連選字開了分支、還沒送訊息的空分支也一樣。前端又沒有檢查回應，所以對話還在，畫面卻沒有任何提示。

沒有分支的對話不受影響：2、4、10 則訊息的對話各測 30 次都成功。

2概念：外鍵與循環引用

外鍵是資料庫的保證：「這個欄位指向的那一列一定存在」。要刪被引用的列，資料庫會拒絕。

message 和 branch 互相引用：

欄位指向意思
branch.anchor_message_idmessage分支從哪則回覆分岔
branch.root_message_idmessage分支的第一則訊息
branch.attach_root_idmessage幽靈分支所屬對話的樹根
branch.parent_branch_idbranch巢狀分支的上層
message.branch_idbranch訊息屬於哪條分支

因此「先刪訊息」會被 branch.anchor_message_id 擋住，「先刪分支」會被 message.branch_id 擋住。不管先刪哪一邊都會失敗，要先解開其中一邊的引用。

清掉 branch 指向 message 的欄位
→
刪 message
→
刪 branch

3概念：交易

上面三步放在同一個交易裡，只有 commit 成功才生效。中間任何一步失敗就 rollback，資料回到刪除前。使用者不會遇到「訊息刪了一半」的對話。

另外，PostgreSQL 的一般外鍵是在每個 SQL 指令結束時才檢查。用一條 DELETE ... WHERE id IN (...) 刪掉整棵樹，父子同時消失，不必再一層一層由深到淺刪。

4刪除範圍怎麼算

沿 parent_id 往下走只找得到對話樹內的訊息。幽靈分支的第一則訊息已經斷開 parent_id，要透過 attach_root_id 才找得到，而幽靈的訊息上也可能還有分支。所以要重複擴大範圍，直到找不到新資料為止：

# 示意，實際程式由 implementer 依規格撰寫
messages = 對話根的所有子孫
repeat:
    branches = 所有引用 messages 的分支
             + messages 所屬的分支
    messages += 這些分支的訊息與子孫
until 兩個集合都不再變大
注意：開始刪除前要確認範圍內的資料都屬於目前的使用者。正常情況不會混到別人的資料；萬一發生，整個刪除會中止，一筆都不動。
分支種類刪除對話時
inline 高亮分支一起刪
底部入口分支一起刪
空分支（沒有訊息）一起刪
屬於這個對話的幽靈分支一起刪，連同它的訊息
attach_root_id 為空的舊幽靈不動：查不出屬於哪個對話
別的對話的分支不動

5概念：HTTP 錯誤不等於 fetch 失敗

fetch 只有連不上伺服器時才會丟錯。伺服器回 404 或 500 仍算「成功收到回應」，所以 try/catch 接不到，要自己檢查 res.ok：

// 現在：500 也當成功，直接刷新列表
await apiFetch(`/chats/${chatId}`, { method: 'DELETE' });

// 修正後的判斷
const res = await apiFetch(`/chats/${chatId}`, { method: 'DELETE' });
// 401：apiFetch 已切到登入頁，不再提示
// 404：對話已不存在（例如另一個分頁刪了），刷新列表即可
// 其他非 ok：顯示錯誤，對話留在列表

6概念：錯誤細節不要回給使用者

現在的 500 回應是 f"刪除失敗: {str(e)}"，資料庫錯誤字串可能包含 SQL、資料表名和資料 id。細節應該只寫進 server log，回應只放固定訊息。

7生成中刪除

背景生成完成時，run_generation 會先查這則訊息；查不到就不寫入，所以生成途中刪除不會出錯，這部分不用改。規格仍會加一項測試，避免之後改壞。
