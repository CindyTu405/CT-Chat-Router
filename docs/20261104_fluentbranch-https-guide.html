網域與 HTTPS

Cloudflare proxy 要不要開、521 為什麼出現，以及 fluentbranch.com 上線前要改什麼。

1先看結論

  • Proxy 維持開啟（橘色雲朵）。Cloudflare 會擋在 EC2 前面，隱藏真實 IP，也處理瀏覽器端的憑證。
  • SSL 模式最後要用 Full (strict)，不要選 Flexible。
  • 有一件事比 HTTPS 更急：目前 API 沒有登入保護，網域又讓網站更容易被發現，請先看第 2 節。

2上線前的安全缺口

現在任何人都可能使用這個網站。backend/main.py 沒有任何路由使用 get_current_user，前端也沒有登入入口。這就是 BACKLOG.md 的 S-U1。

HTTPS 只保護傳輸過程，不會判斷「這個人能不能用」。S-U1 完成前的風險：

  • 陌生人可以呼叫 /chat，消耗平台的模型額度。
  • 知道 session_id 或訊息 id，就能讀寫別人的對話。
  • 新憑證會記錄在公開的憑證透明度日誌中，自動掃描器很快就會發現新網域。

S-U1 完成前的門禁

做法優點缺點
Cloudflare Access（建議）進站前要先用白名單 Email 驗證，換網路也能用，不必改程式要設定 Zero Trust；測試者都要加入白名單
WAF 只允許你的 IP設定最簡單家用 IP 會變，手機網路也容易被擋
維持公開不用設定承擔上述全部風險，不建議

Access 只是臨時門禁，正式對外前仍要完成 S-U1。

開啟 proxy 後，一次連線其實分成兩段。Cloudflare 自動處理 A 段的憑證，B 段則由 SSL 模式決定：

SSL 模式B 段評價
FlexibleHTTP，未加密❌ 網址列有鎖頭，但 Cookie 和對話內容在 B 段是明文
FullHTTPS，但不驗證憑證⚠️ 有加密，但無法確認對方真的是你的伺服器
Full (strict)HTTPS，並驗證憑證✅ 我們要用這個
別用 Flexible 消除 521。它能讓錯誤立刻消失，因為 Cloudflare 改走 port 80，但 B 段會變成明文，還可能和 nginx 的 HTTP 轉 HTTPS 形成無限轉址。

Proxy 開或關

開啟（橘色雲朵）關閉（灰色雲朵，DNS only）
EC2 IP隱藏公開
DDoS 防護、WAF、Access可用大多不可用
憑證Origin Certificate，一次可設定很多年要自己申請並自動續期，例如 Let's Encrypt
長時間無回應約 100 秒會得到 524只受你自己的 nginx 限制（目前 300 秒）

商用服務需要防護，所以選開啟。串流持續有資料時不會觸發 524，要注意的是模型遲遲不回第一個字的情況。

5要改的程式

① 憑證放在 VM，不進 git

Origin Certificate 由 Cloudflare 簽發，只有 Cloudflare 信任，正好適合 B 段。私鑰不能 commit，也不要貼到聊天中。

# VM 上執行；憑證與私鑰的內容從 Cloudflare 後台貼入
sudo mkdir -p /etc/fluentbranch/tls
sudo nano /etc/fluentbranch/tls/origin.pem
sudo nano /etc/fluentbranch/tls/origin.key
sudo chmod 600 /etc/fluentbranch/tls/origin.key

② docker-compose.prod.yml

api:
  command: uvicorn main:app --host 0.0.0.0 --port 8000 --root-path /api --forwarded-allow-ips '*'
  environment:
    # 保留原本三項，再加上：
    - SESSION_SECRET_KEY=${SESSION_SECRET_KEY:?SESSION_SECRET_KEY is required}
    - SESSION_COOKIE_SECURE=true
    - FRONTEND_URL=https://fluentbranch.com
    - CORS_ORIGINS=https://fluentbranch.com
    - ALLOWED_MODELS=${ALLOWED_MODELS:-gemini*}
    - GOOGLE_CLIENT_ID=${GOOGLE_CLIENT_ID:-}
    - GOOGLE_CLIENT_SECRET=${GOOGLE_CLIENT_SECRET:-}
    - GITHUB_CLIENT_ID=${GITHUB_CLIENT_ID:-}
    - GITHUB_CLIENT_SECRET=${GITHUB_CLIENT_SECRET:-}

web:
  ports:
    - "80:80"
    - "443:443"
  volumes:
    - ./frontend/nginx.prod.conf:/etc/nginx/conf.d/default.conf:ro
    - /etc/fluentbranch/tls:/etc/nginx/tls:ro
為什麼 --forwarded-allow-ips '*' 在這裡可以接受：api 沒有對外開 port，只有 compose 內網的 nginx 連得到它。如果 api 直接對外，這個設定就會讓任何人偽造 IP。

③ 新增 frontend/nginx.prod.conf

正式環境另用一個檔案，原本的 nginx.conf 不動，開發環境不必準備憑證。

# 掃描 IP 或未知網域的連線，直接拒絕
server {
    listen 443 ssl default_server;
    ssl_reject_handshake on;
}

# HTTP 和 www 都轉到正式網址
server {
    listen 80 default_server;
    return 301 https://fluentbranch.com$request_uri;
}
server {
    listen 443 ssl;
    server_name www.fluentbranch.com;
    ssl_certificate     /etc/nginx/tls/origin.pem;
    ssl_certificate_key /etc/nginx/tls/origin.key;
    return 301 https://fluentbranch.com$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name fluentbranch.com;
    ssl_certificate     /etc/nginx/tls/origin.pem;
    ssl_certificate_key /etc/nginx/tls/origin.key;

    # 只相信 Cloudflare 傳來的真實 IP；清單來自 cloudflare.com/ips
    set_real_ip_from 203.0.113.0/24;   # 範例，實作時換成官方完整清單
    real_ip_header CF-Connecting-IP;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://api:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto https;

        proxy_http_version 1.1;
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}

X-Forwarded-For 故意不用 $proxy_add_x_forwarded_for，避免把使用者自己送來的假 IP 一起傳下去。

④ Cloudflare 後台

  1. SSL/TLS → Origin Server → 建立憑證，涵蓋 fluentbranch.com 和 *.fluentbranch.com。
  2. 確認新設定可用後，把模式改成 Full (strict)。
  3. SSL/TLS → Edge Certificates → 開啟 Always Use HTTPS。
  4. EC2 Security Group：443 只開放 Cloudflare 的 IP，移除 80 的對外開放，SSH 維持只限你的 IP。這樣別人就無法用 IP 繞過 Cloudflare。
  5. 穩定運行一陣子後再開 HSTS，先用短時間，也先不要開 Preload。HSTS 開了之後不容易退回 HTTP。

Cloudflare 的選單名稱可能和這裡略有不同，以後台為準。

6步驟與驗收

順序很重要：先讓 443 準備好，再切換模式，網站才不會中斷。

編號誰做內容
H0你依第 2 節設定臨時門禁
H1你確認 Elastic IP、建立 Origin Certificate、放到 VM、在 VM 的 .env 加入 SESSION_SECRET_KEY
H2implementer新增 nginx.prod.conf，修改 docker-compose.prod.yml
H3你VM 上 git pull 並 sudo docker compose up -d --build，切換 Full (strict)，開啟 Always Use HTTPS
H4你收緊 Security Group
