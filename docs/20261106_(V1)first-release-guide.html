CT-Chat-Router · V1

正式初版

額度、模型、安全標頭、備份、監控與隱私權說明。每一項都先講它防的是什麼。

1額度：為什麼要自己記次數

現有的「每分鐘 10 次」只擋短時間連發。一個人慢慢送，一天仍可能送上千次。每日額度要有地方記住今天用了幾次，所以需要一張新資料表：

daily_usage
  user_id, day, count      # 每人每天一列，day 是台灣日期

為什麼不直接數訊息？因為訊息可以刪。用數的話，刪掉對話就等於退回額度。

同時送出時不能多算

兩個分頁同時送出時，如果先讀「用了 19 次」再寫回 20，兩邊都會通過。要把檢查和加一放進同一條 SQL，由資料庫保證一次只處理一個：

INSERT INTO daily_usage (user_id, day, count) VALUES (:u, :d, 1)
ON CONFLICT (user_id, day) DO UPDATE SET count = daily_usage.count + 1
WHERE daily_usage.count < :limit
RETURNING count;   -- 沒有回傳任何列 = 額度已滿

全站上限

OpenRouter 免費模型的每日額度是整個帳號共用。全站上限的作用，是在 OpenRouter 開始拒絕之前先告訴用戶今天額度已滿。它是保護用的軟上限，同時送出時多幾次也無妨。

OpenRouter 額度（2026-11-06 查詢）：累計購買未滿 10 美元每日 50 次，達到後每日 1000 次，每分鐘都是 20 次。失敗的請求也算。數字可能變動。

2拔掉 Gemini：前後端要一致

後端白名單決定「能不能用」，前端選單決定「看得到什麼」。兩邊不一致，用戶就會選到不能用的模型。所以改成由後端告訴前端：

GET /api/model-options
{ "presets": [], "default_model": "某個免費模型" }  // 正式站
{ "presets": ["gemini-2.5-flash-lite"], ... }       // 本機

正式站把 ALLOWED_MODELS 設成 none，沒有模型叫這個名字，等於不開放任何固定模型，只留 OpenRouter 免費清單。不能留空，因為 compose 設定遇到空值會退回 gemini*。

免費模型會隨時下架，所以設定的預設模型不在清單裡時，要自動改用清單第一個。

3輸出上限

限制每則回覆最多 1500 tokens，避免單次請求跑太久。代價是很長的回答可能被截斷，所以做成環境變數，之後可以調整。

4安全標頭：請瀏覽器幫忙把關

回應標頭是伺服器附給瀏覽器的指示。程式有疏漏時，這些標頭是第二道防線。

標頭防什麼
Strict-Transport-Security之後都強制走 HTTPS，避免被降級成明文連線
Content-Security-Policy限制腳本來源。就算有人塞進惡意腳本，瀏覽器也拒絕執行
X-Frame-Options不讓別的網站嵌入，防止誘騙點擊
X-Content-Type-Options不讓瀏覽器猜檔案類型，避免把檔案當腳本執行
Referrer-Policy點外部連結時，不把完整網址洩漏給對方
Permissions-Policy關閉用不到的相機、麥克風、定位權限
注意：CSP 太嚴會讓網站壞掉，部署後要實際操作一輪，並檢查瀏覽器 Console 有沒有被擋的項目。

5日誌上限

Docker 預設會一直累積容器日誌。硬碟滿了，資料庫也會無法寫入。設定每個容器最多 5 個、每個 10 MB 的檔案，舊的自動刪除。

6備份：有備份不等於能還原

備份要防的是硬碟損毀、誤刪和錯誤的 migration。建議用 AWS 的 EBS 快照：每天把 VM 硬碟拍一份，存在硬碟之外。

  1. 到 AWS 主控台：EC2 → Elastic Block Store → Lifecycle Manager。
  2. 建立 EBS snapshot 政策，目標選 VM 的硬碟（先幫硬碟或 VM 加一個標籤，例如 Backup=daily）。
  3. 排程每天一次，保留 7 份。
  4. 隔天確認 Snapshots 頁面出現新快照。

還原演練

從快照建立一顆新硬碟，掛到一台臨時 VM，啟動 PostgreSQL 並查詢訊息筆數。確認後刪除臨時 VM 和硬碟，正式站完全不受影響。實際操作時我會逐步帶你做。

費用：快照和臨時 VM 都會收少量 AWS 費用，實際金額以 AWS 帳單為準。

7當機通知

外部監控服務每隔幾分鐘連一次網站，連不上就寄信給你，例如 UptimeRobot 的免費方案。它必須在外部運作，因為 VM 掛掉時，VM 上的程式也沒辦法通知你。等 Cloudflare Access 拿掉後再設定，否則它測到的只是 Access 的登入頁。

8隱私權說明

別人的對話會存在你的資料庫，用戶有權知道。第一版用白話寫清楚：

  • 收集什麼：登入 email、登入服務商，以及對話內容。
  • 給誰：對話會送到 OpenRouter 和模型供應商。免費模型可能記錄內容，請勿輸入敏感資料。
  • 誰看得到：其他用戶看不到；站長有資料庫權限，技術上可以存取。
  • 怎麼刪除：用戶可以自己刪對話；刪帳號要聯絡站長。

頁面做成靜態檔 privacy.html，不用登入也能看。公開開放前必須補上聯絡信箱。

注意：這是基本說明，不是法律意見。要收費或用戶變多時，建議請專業人士看過。
