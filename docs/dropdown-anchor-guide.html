下拉選單與錨點：面板是怎麼「貼」在按鈕上的

模型選單的面板要出現在按鈕的正上方或正下方，而且不能超出螢幕。這篇解釋它用到的 CSS 定位、翻轉判斷，以及為什麼要用置中錨點。

0. 結論先講

  • 面板是按鈕的子元素，用 position: absolute 定位，相對於按鈕所在的容器（position: relative）。
  • 水平位置由「錨點」決定：現在是 置中（left-1/2 -translate-x-1/2）。
  • 垂直位置由 top-full（在下方）或 bottom-full（在上方）決定。上下方向由 JavaScript 量測空間後決定，這叫「翻轉」。
  • 點擊面板外要關閉，是監聽整個文件的 mousedown 事件，判斷點擊目標是否在容器內。

1. 基礎：position 與參考容器

position: absolute 的元素不佔版面，位置由「最近的、本身有定位（relative／absolute／fixed）的祖先」決定。這個祖先就叫參考容器。

<div class="relative">          <!-- 參考容器 -->
  <button>選模型</button>
  <div class="absolute top-full">   <!-- 面板：位於參考容器的底部之下 -->
    ...
  </div>
</div>
為什麼容器要是按鈕的父層？
如果參考容器是整個頁面，面板會飄到頁面的某個角落。把參考容器縮到剛好包住按鈕，面板的 top-full 就會緊貼按鈕底邊，left-1/2 就是按鈕的中間。

2. 錨點：水平方向的對齊

「錨點」是面板與按鈕對齊的那一點。同一個面板可以錨在不同位置：

寫法面板的哪一邊對齊按鈕何時用
left-0面板左緣 = 按鈕左緣按鈕在畫面最左側
right-0面板右緣 = 按鈕右緣按鈕在畫面最右側（舊版用這個）
left-1/2 -translate-x-1/2面板中心 = 按鈕中心按鈕在中間，要對稱展開（現在用這個）

為什麼 left-1/2 還要加 -translate-x-1/2？

left-1/2 只會把面板的左緣放在參考容器寬度的 50%，面板會偏右。要讓面板的中心落在 50%，要再往左移動自己寬度的一半，這就是 -translate-x-1/2（translateX(-50%)）。

注意：寬度大於容器時
面板是置中的，所以寬度超過按鈕的一半，左右都會超出按鈕範圍。在手機（375px）寬時，要確認面板左右都還在螢幕內。我們用 max-w-[calc(100vw-2rem)] 限制面板最寬不超過螢幕寬度減 2rem，並在 375px 量測過：面板左 43px、右 299px，都在螢幕內。

3. 垂直方向：翻轉（flip）

按鈕在輸入框下方，靠近螢幕底部，下方空間不夠。這時面板要改到按鈕上方展開。這個判斷要用 JavaScript 做，CSS 本身無法知道「剩多少空間」。

// 面板展開後量測
const rect = buttonRef.current.getBoundingClientRect();
const spaceBelow = window.innerHeight - rect.bottom;   // 按鈕下方剩餘高度
const spaceAbove = rect.top;                            // 按鈕上方剩餘高度
const needed = panelRef.current.offsetHeight + 8;       // 面板高度 + 8px 間隙

setDropUp(spaceBelow < needed && spaceAbove > spaceBelow);

為什麼用 useLayoutEffect 而不是 useEffect？

兩者都在面板展開後執行，差別在時機：

  • useEffect：瀏覽器可能已經先畫出一幀，使用者會看到面板先出現在錯的位置，再跳到正確位置（閃爍）。
  • useLayoutEffect：在瀏覽器繪製之前同步執行，改變 dropUp 後會在同一幀內完成重新渲染，使用者看不到錯誤位置。
判斷原則
需要「先量測、再決定版面」時用 useLayoutEffect；只是跟外部系統同步（例如註冊事件）用 useEffect。

class 的切換

className={`absolute left-1/2 -translate-x-1/2 ... ${
  dropUp ? 'bottom-full mb-1' : 'top-full mt-1'
}`}

bottom-full 是面板底邊對齊按鈕頂邊（向上），top-full 是面板頂邊對齊按鈕底邊（向下）；mb-1／mt-1 留 4px 間隙。

4. 關閉與點擊判斷

面板是開著的 UI，點擊面板外應該關閉。做法是在 document 上監聽 mousedown，判斷點擊的目標是不是在容器內：

const handlePointerDown = (e) => {
  if (wrapperRef.current && !wrapperRef.current.contains(e.target)) setOpen(false);
};
document.addEventListener('mousedown', handlePointerDown);
document.addEventListener('touchstart', handlePointerDown);
  • 為什麼是 mousedown 而不是 click？mousedown 在按下時就觸發，比 click（放開才觸發）快，面板會先關閉，不會與其他操作衝突。
  • 為什麼要 removeEventListener？effect 的清理函式會在面板關閉時移除監聽，避免記憶體洩漏，也避免關閉後仍然響應。
  • 為什麼 wrapperRef 包住的是按鈕和面板？面板是按鈕的子元素，所以點面板本身不算「外面」，不會誤關閉。
