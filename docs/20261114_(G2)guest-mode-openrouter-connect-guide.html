CT-Chat-Router · G2

訪客模式與 OpenRouter 授權連線

讓沒登入的人先試用，登入後把試用對話帶走；登入的人接上自己的 OpenRouter 帳號，用自己的額度。這份教學說明背後的概念、為什麼這樣設計，以及安全上要守住什麼。

1要解決的問題

  • 首頁看完示範，按「開始使用」卻要先登入，很多人會在這裡離開。
  • 平台的 OpenRouter 免費額度是整個帳號共用的。使用者一多，大家一起被擋。

做法分兩塊：訪客模式讓人不登入就能試 10 則；OpenRouter 授權連線讓登入的人改用自己的帳號，不再占用平台額度。

身分用誰的金鑰每日則數可用模型對話保存
訪客（沒登入）平台10免費模型7 天沒活動就刪除
已登入、未連結平台10免費模型到自己刪除為止
已登入、已連結自己的不限任何模型 ID到自己刪除為止

前兩種在規格裡合稱「試用者」。

2概念：訪客也是一個使用者

現在每則訊息、每條分支都有 user_id，每個 API 都先用 get_current_user 從 cookie 找出使用者，再檢查資料是不是他的。

訪客模式不另外做一套。按下「開始使用」時，後端建立一列 User，oauth_provider 填 "guest"，再發一個跟登入一樣的 session cookie。之後這個瀏覽器送來的每個請求，後端看到的就是「一個使用者」，原本的擁有者檢查一行都不用改。

按「開始使用」
→
POST /auth/guest
→
建立訪客 User
發 session cookie
→
進入聊天
為什麼不用 IP 當身分：同一個 IP 後面可能是整間公司或整個電信業者的用戶，用 IP 當身分會讓不相干的人看到彼此的對話。IP 只拿來限制次數，身分靠 cookie。
為什麼不把訪客對話存在瀏覽器：那樣後端要多一條「沒有使用者」的路徑，串流、分支、重新生成全部要寫兩份，登入時還要把瀏覽器的資料上傳合併。讓訪客成為使用者，登入時只要改 user_id。

3概念：三層額度

訪客清掉 cookie 就會變成一個新的訪客，所以只限制「每個訪客 10 則」不夠。額度有三層，任何一層滿了就擋：

層上限對象擋下時
個人每天 10 則每個試用者429 daily_quota_exceeded
IP每天 10 個訪客身分、100 則只算訪客429 guest_ip_limit
全站每天 900 則所有試用者合計503 site_quota_exceeded

IP 不存原文，存雜湊

要數「這個 IP 今天用了幾次」，不需要知道 IP 是多少，只要每次算出同一個代號。

ip_hash = HMAC-SHA256(key=IP_HASH_SECRET, msg="203.0.113.7")
# 同一個 IP 永遠得到同一串；沒有 IP_HASH_SECRET 的人無法從這串反推 IP
為什麼要加密鑰（HMAC）而不是直接 SHA-256：IPv4 只有 43 億個，直接雜湊可以把全部 IP 算一遍做成對照表。加了只有伺服器知道的密鑰，資料庫外洩時別人也對不回去。

不會超發的計數

20 個請求同時到，如果「先讀次數、判斷、再加一」分三步做，可能 20 個都讀到 9 然後都通過。現有的每日額度已經用一句 SQL 解決，新的 IP 計數用同一個寫法：

INSERT INTO guest_ip_usage (ip_hash, day, messages) VALUES (:h, :d, 1)
ON CONFLICT (ip_hash, day) DO UPDATE SET messages = guest_ip_usage.messages + 1
WHERE guest_ip_usage.messages < :limit
RETURNING messages
-- 沒有回傳列 = 已經滿了。判斷和加一在資料庫裡是同一個動作。
防止換身分洗額度：訪客用了 7 則再登入，登入帳號當天只剩 3 則。登入的那一刻，後端把訪客當天的次數加到帳號上。

4概念：登入時把試用對話帶走

登入成功後，瀏覽器的 session cookie 換成登入帳號的。訪客原本的 token 不丟掉，改放到另一個 httpOnly cookie guest_session（有效 1 天）。

訪客按登入
→
OAuth 回來
session = 帳號
guest_session = 訪客
→
詢問：移到帳號？
→
移入：改 user_id
刪除：整批刪掉

「移到帳號」在資料庫裡就是把訪客的訊息和分支的 user_id 改成登入帳號，再刪掉訪客那一列。

安全重點：搬移的請求不帶任何 id。後端只認兩個 cookie：session 說明「搬到誰」，guest_session 證明「你就是那個訪客」。攻擊者沒有受害者瀏覽器裡的訪客 token，就搬不走別人的對話。
為什麼要問而不是自動搬：共用電腦上，前一個人試用留下的對話，不應該自動併進下一個登入的人的帳號。

5概念：過期資料的清理

訪客 7 天沒有活動，就連同對話一起刪除。User 多一個欄位 last_active_at，每次送訊息時更新。

後端啟動時開一個背景工作，每小時跑一次清理。清理是會卡住的資料庫操作，所以用 asyncio.to_thread 丟到別的執行緒做，不擋住正在串流的請求（現有的生成寫回也是這樣做的）。

6概念：OpenRouter 授權（OAuth PKCE）

目的：讓使用者把「用我 OpenRouter 帳號的權限」交給我們，但不用把密碼或金鑰複製貼上。

按「連結 OpenRouter」
→
後端產生
verifier 與 state
導向 openrouter.ai/auth
→
使用者在 OpenRouter
按同意
→
導回本站
帶 code 與 state
→
後端用 code + verifier
換到 API 金鑰

PKCE 在防什麼

code 會出現在網址上，可能被瀏覽器紀錄、外掛、代理伺服器看到。PKCE 讓「只有 code」沒有用：

code_verifier  = 隨機字串（只留在我們的後端）
code_challenge = BASE64URL(SHA256(code_verifier))   # 這個才送給 OpenRouter

# 換金鑰時要交出 code_verifier。OpenRouter 自己算一次 SHA256，
# 和當初收到的 code_challenge 對得上才給金鑰。
# 偷到 code 的人沒有 verifier，換不到。

state 在防什麼

攻擊者可以先用自己的 OpenRouter 帳號走到「導回本站」那一步，把那個網址騙受害者點開。如果後端照單全收，受害者的帳號就接上了攻擊者的 OpenRouter，受害者之後的對話內容全都經過攻擊者的金鑰。

state 是後端在發起時產生、存在自己 session 裡的隨機值。導回來時要帶同一個值，而且 session 裡記的發起人要等於目前登入的人。不是自己發起的回呼一律拒絕，用過一次就作廢。

和 Google／GitHub 登入的差別：那兩個是「確認你是誰」，換到的資料用完就丟。OpenRouter 這個是「拿到一把可以花錢的金鑰」，之後每次呼叫模型都要用，所以必須保存。文件沒有說這把金鑰會過期，也沒有 refresh token；使用者可以在 OpenRouter 的金鑰頁撤銷它。

7概念：金鑰的加密保存

密碼可以只存雜湊，因為驗證時只要比對。金鑰不行：我們每次都要拿「原文」去呼叫 OpenRouter，所以要用可以解回來的加密。

from cryptography.fernet import Fernet

f = Fernet(CREDENTIAL_ENCRYPTION_KEY)      # 加密金鑰只放在 VM 的 .env
密文 = f.encrypt(b"sk-or-v1-...")           # 存進資料庫的是這個
原文 = f.decrypt(密文)                       # 要呼叫模型時才解開，只存在記憶體

Fernet 除了加密，還會附上驗證碼：密文被改過或用錯加密金鑰，解密會直接失敗，不會解出一串亂碼。

情況結果
只有資料庫外洩（備份外流、SQL injection）拿到的是密文，解不開
VM 整台被入侵密文和加密金鑰都在，擋不住。靠使用者在 OpenRouter 設的花費上限限制損失
加密金鑰遺失或更換所有連結失效，使用者重新連結即可，對話不受影響
金鑰不能出現的地方：API 回應、log、錯誤訊息、前端。/auth/me 只回「有沒有連結」。SQL_ECHO 開著時會把 SQL 參數印出來，正式站必須關閉。

產生加密金鑰（部署時做一次）

python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
# 把輸出放進 VM 的 .env：CREDENTIAL_ENCRYPTION_KEY=...

8概念：用自己的金鑰生成，以及失效時怎麼辦

現在後端只有一個 OpenRouter client，用平台金鑰。改成：已連結的人每次生成時，用他的金鑰建立 client。

async def openrouter_chat_stream(message, history, model_name, api_key=None):
    c = AsyncOpenAI(base_url=..., api_key=api_key) if api_key else client
    ...
OpenRouter 回應意思我們怎麼做
401金鑰被撤銷刪除連結，回覆顯示「你的 OpenRouter 連結已失效，請重新連結」
402帳號額度不足保留連結，回覆顯示「你的 OpenRouter 帳號額度不足」
其他錯誤現有的「生成中斷，請稍後再試」
絕不悄悄改用平台金鑰：已連結的人可能正在用付費模型。失敗時改用平台金鑰重試，等於讓平台替他付錢，也讓他以為連結還正常。
已連結者一律走 OpenRouter：程式裡模型名稱以 gemini 開頭會走直連 Google 的路徑，那條路用的是平台的 Google 金鑰（正式站已經沒有這把金鑰，只剩本機測試用）。已連結者可以輸入任何模型 ID，所以要先擋掉這條路。

11練習

  1. 訪客 A 知道訪客 B 某則訊息的 id，直接呼叫 GET /chats/{id}/history 會得到什麼？是哪一段既有的程式擋下的？
  2. 如果 IP 只用 SHA-256 不加密鑰，拿到資料庫的人要怎麼找出某個雜湊對應的 IPv4？大概要算幾次？
  3. 「先 SELECT 次數、在 Python 判斷、再 UPDATE 加一」在 20 個併發請求下會發生什麼事？一句 INSERT ... ON CONFLICT ... WHERE 為什麼不會？
  4. 搬移對話的 API 如果改成收一個 guest_user_id 參數，會出現什麼攻擊？
  5. OpenRouter 回呼少了 state 檢查時，攻擊者可以怎麼讓受害者的對話經過攻擊者的金鑰？
  6. 為什麼金鑰用 Fernet 加密而不是像 session token 一樣存 SHA-256？
  7. 已連結者的金鑰回 401 時，如果程式自動改用平台金鑰重試，會造成哪兩個問題？
