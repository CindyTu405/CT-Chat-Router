手機版標題與輸入框跑出畫面

100vh 在手機上為什麼比畫面高、dvh／svh／lvh 的差別、用 @supports 保留舊瀏覽器的退路。

1症狀與目標

  • 手機開啟對話頁：上方標題列或下方輸入框有一部分在畫面外，要把整頁捲到最頂或最底才看得完整。
  • 目標：整頁剛好等於「目前看得到的區域」，標題與輸入框固定在畫面內，只有訊息區捲動。
  • 鍵盤彈出時目前正常，不在這次範圍。

2概念一：手機的 100vh 不是「看得到的高度」

App 最外層是 h-screen，也就是 height: 100vh。桌面上 100vh 就是視窗高度，沒有問題。

手機瀏覽器的網址列會在捲動時收起、展開。如果 100vh 跟著變，每次網址列動一下整頁就重新排版、跳動，所以瀏覽器把 100vh 固定成網址列收起時的最大高度。

數字只是示意，實際差距是網址列（和部分瀏覽器的底部工具列）的高度。

3概念二：三種新的高度單位

單位意思網址列顯示時網址列收起時
lvh（large）最大可見高度，等於舊的 vh比畫面高（現在的問題）剛好
svh（small）最小可見高度剛好比畫面矮，底部空一截
dvh（dynamic）目前實際可見高度，跟著網址列變剛好剛好

採用 dvh。它會在網址列伸縮時重新排版，但我們的頁面本身不捲動（只有訊息區捲），網址列幾乎不會收起，所以不會一直跳動。

鍵盤：多數手機瀏覽器開鍵盤時不會縮小 dvh（鍵盤蓋在頁面上，瀏覽器自己把焦點捲進可見範圍）。你回報目前鍵盤正常，所以這次不動。

4概念三：舊瀏覽器的退路（@supports）

dvh 支援：iOS Safari 15.4+、Chrome 108+。更舊的瀏覽器看不懂 100dvh，會整條忽略，高度變成 auto，版面反而會壞。所以保留 h-screen 當底，只有支援時才換成 dvh：

{/* App.jsx 最外層（現在） */}
<div className="flex h-screen ...">

{/* 改成 */}
<div className="flex h-screen supports-[height:100dvh]:h-dvh ...">

Tailwind 產生的 CSS：

.h-screen { height: 100vh; }
@supports (height: 100dvh) {
  .supports-\[height\:100dvh\]\:h-dvh { height: 100dvh; }
}

@supports 是 CSS 的條件判斷：瀏覽器支援括號裡的寫法才套用裡面的規則。只寫 h-screen h-dvh 兩個 class 不行：兩者都設定 height，哪個生效取決於 Tailwind 產生 CSS 的順序，不是 class 的書寫順序。

5其他滿版元素要不要改

元素寫法要改嗎
App 最外層h-screen要（本次唯一改動）
手機側邊欄、分支面板 drawer（F5）fixed inset-0不用：fixed＋上下都貼 0，高度由瀏覽器依可見區域決定，不經過 vh
分支地圖彈窗fixed inset-0不用，同上
