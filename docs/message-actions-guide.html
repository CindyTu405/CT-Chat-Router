訊息功能列與複製

一張 actions 清單產生按鈕與選單；Clipboard API 與「安全環境」；http 下怎麼複製；手機長按選單。

1要做成什麼樣子

電腦（≥ 768px）手機（< 768px）
AI 訊息模型名稱下方一排功能列，常態顯示
user 訊息送出時間右邊一排功能列，常態顯示不顯示功能列；長按氣泡跳出選單

目前功能列只有「複製」一項，但之後還會加（例如重傳、編輯）。所以重點不是做一顆複製鈕，而是做一個能長出更多按鈕的功能列。

做在 G3 的共用 MessageList 裡，分支面板會自動一起有。

2概念一：用清單產生按鈕

把「有哪些功能」寫成資料，畫面只負責把資料畫出來：

// 每個功能 = 一筆資料
const buildMessageActions = (msg) => [
  {
    id: 'copy',
    label: '複製',
    icon: Copy,
    run: () => copyText(msg.content),   // 原始 markdown
  },
  // 之後加功能：在這裡多一筆，功能列和手機選單同時出現
];

同一張清單有兩種畫法：

buildMessageActions(msg)
→
MessageActions
一排小圖示（電腦／AI）
＋
MessageActionMenu
長按選單（手機 user）
好處：加一個功能只改清單一處，不會出現「功能列有、手機選單忘了加」。

3概念二：Clipboard API 與「安全環境」

現代瀏覽器寫入剪貼簿的標準做法：

await navigator.clipboard.writeText('要複製的文字');

但它有一個限制：只在「安全環境」（secure context）可用。不是安全環境時，navigator.clipboard 直接是 undefined，呼叫就報錯。

網址安全環境？navigator.clipboard
https://任何網域✅可用
http://localhost:5173、http://127.0.0.1✅（瀏覽器特例）可用
http://192.168.x.x:5173（手機連電腦）❌undefined

為什麼要限制：剪貼簿可能有密碼等敏感資料，瀏覽器不想讓「可能被中間人竄改的 http 頁面」碰它。

可以在 console 確認：window.isSecureContext → true / false。

4http 下怎麼辦：三種解法

① 備援寫法（決定採用）

舊的 document.execCommand('copy') 沒有安全環境限制。做法是暫時放一個看不見的 textarea、選取它的內容、執行複製、再移除：

// frontend/src/clipboard.js
export async function copyText(text) {
  if (window.isSecureContext && navigator.clipboard) {
    try {
      await navigator.clipboard.writeText(text);
      return true;
    } catch {
      // 權限被拒等狀況 → 往下走備援
    }
  }
  const ta = document.createElement('textarea');
  ta.value = text;
  ta.setAttribute('readonly', '');                 // 手機不跳鍵盤
  ta.style.position = 'fixed';
  ta.style.opacity = '0';
  document.body.appendChild(ta);
  ta.select();
  let ok = false;
  try { ok = document.execCommand('copy'); } catch { ok = false; }
  document.body.removeChild(ta);
  return ok;
}

execCommand 已被標為「不建議使用」，但各大瀏覽器都還支援。這裡只當備援：換成 https 後走的是第一段，備援不會被用到，也不用拿掉。

② 開發時讓 Vite 走 https

裝 @vitejs/plugin-basic-ssl，vite.config.js 加進 plugins，開發伺服器就變 https://192.168.x.x:5173。缺點：自簽憑證，手機第一次要手動按「仍要前往」；後端 API 如果還是 http，會被瀏覽器擋（混合內容），要一起處理。

③ 手機透過 USB 轉發成 localhost

Android：Chrome 的 chrome://inspect → Port forwarding，把手機的 localhost:5173 轉到電腦。手機開 http://localhost:5173 就是安全環境。缺點：要接線、只適用 Android＋Chrome。

解法改 code手機額外操作上線後
① 備援寫法約 10 行無保留無害
② Vite https設定檔＋後端也要 https信任自簽憑證不影響
③ USB 轉發無每次接線不影響

5概念三：偵測長按

瀏覽器沒有「長按」事件，要自己組：手指按下時開計時器，時間到還沒放開、也沒移動，就算長按。

const LONG_PRESS_MS = 500;
const MOVE_TOLERANCE = 10;   // 手指移動超過 10px 視為在捲動，不算長按

onPointerDown={(e) => {
  if (e.pointerType !== 'touch') return;      // 只處理手指，滑鼠不觸發
  start = { x: e.clientX, y: e.clientY };
  timer = setTimeout(() => openMenu(bubbleEl), LONG_PRESS_MS);
}}
onPointerMove={(e) => { if (移動距離 > MOVE_TOLERANCE) clearTimeout(timer); }}
onPointerUp={() => clearTimeout(timer)}
onPointerCancel={() => clearTimeout(timer)}
onContextMenu={(e) => e.preventDefault()}   // 擋掉 Android 長按的原生選單

跟原生「長按選字」的衝突

手機長按文字，瀏覽器預設會選字並跳出「複製／全選」原生選單，會跟我們的選單打架。所以 user 氣泡在手機上關掉原生選取：

className="max-md:select-none max-md:[-webkit-touch-callout:none]"
  • max-md:：只在 < 768px 生效（Tailwind v4），電腦版照常可以選字。
  • select-none：不能選取文字。
  • -webkit-touch-callout: none：iOS 長按不跳原生選單。
代價（已確認接受）：手機上不能只選 user 訊息的一部分，要整則複製。AI 訊息不受影響，手機長按 AI 文字仍是選字開分支。

6概念四：浮動選單與「點外面關閉」

選單用 position: fixed，以氣泡的 getBoundingClientRect() 決定位置，放在氣泡上方。這跟現有的「建立分支」浮動按鈕是同一個模式（MessageList.jsx 的 branchSel）：

useEffect(() => {
  if (!menu) return;
  const close = () => setMenu(null);
  const onDown = (e) => { if (!menuRef.current?.contains(e.target)) close(); };
  document.addEventListener('pointerdown', onDown);
  window.addEventListener('scroll', close, true);   // 捲動就關
  window.addEventListener('resize', close);
  return () => { ...移除三個監聽... };
}, [menu]);

這裡用 fixed 是對的：選單要浮在所有東西上面，而且只在手機出現（手機的分支面板是滿版，不會有 G3 那種「跑到別的面板」問題）。

8小練習

  1. 用手機開 http://你的電腦IP:5173，在 console（或遠端偵錯）輸入 window.isSecureContext 和 navigator.clipboard，各是什麼？電腦開 http://localhost:5173 再試一次。
  2. 如果要加一個「重傳」功能（G6），要改 buildMessageActions 的哪裡？要不要改 MessageActions 或 MessageActionMenu？
  3. 長按計時器為什麼要在 pointermove 超過 10px 時取消？拿掉的話，手指按在 user 氣泡上往上滑捲動會發生什麼？
  4. 為什麼 select-none 要加 max-md: 前綴？
