user 訊息：保留換行、只認程式碼、超過 10 行摺疊

自己寫一個只認程式碼的小解析器；量測畫面上的實際行數；摺疊與漸層淡出；用 key 讓狀態跟著訊息走。

1要做成什麼樣子

  • user 訊息照原樣顯示：換行、空白都保留；**粗體** 就顯示 **粗體**，不轉成 markdown。
  • 例外只有兩種程式碼：```區塊``` 用跟 AI 一樣的深色語法高亮；`行內` 用 user 氣泡現有的行內樣式。
  • 畫面上超過 10 行就摺疊：底部漸層淡出，氣泡內最下方置中一個 V（展開）；展開後變倒 V（收起）。
  • 展開狀態不記憶；主對話與分支面板都套用（共用 MessageList）。

2概念一：為什麼不用 ReactMarkdown 擋掉其他語法

ReactMarkdown 有 allowedElements 可以只允許 code、pre。但它擋掉的是解析後的結果，不是原文：

使用者輸入allowedElements 擋掉 strong我們要的
**重要**重要（星號已經被吃掉）**重要**
# 標題標題（# 不見）# 標題
單一換行被合併成空白換行

所以改成自己切：只認出兩種程式碼，其餘一律當純文字。

3概念二：只認程式碼的小解析器

分兩層切。先切出 ``` 區塊，剩下的文字再切出 `行內`：

// 1. 程式碼區塊：```語言(可省略) 換行 內容 ```
const FENCE_RE = /```([\w+-]*)\n?([\s\S]*?)```/g;
// 2. 行內程式碼：一對反引號，中間不含換行
const INLINE_RE = /`([^`\n]+)`/g;

parseUserContent('看這段：\n```js\nlet a = 1;\n```\n還有 `b`')
// →
[
  { type: 'text',  text: '看這段：\n' },
  { type: 'fence', lang: 'js', code: 'let a = 1;\n' },
  { type: 'text',  text: '\n還有 ' },
  { type: 'code',  text: 'b' },
]
  • [\s\S]*?：任何字元（含換行），? 表示「盡量少」，遇到第一個收尾 ``` 就停，兩個區塊才不會被當成一個。
  • 沒有收尾的 ```（打到一半）不會被正規式命中，自然留在純文字裡。

純文字用 whitespace-pre-wrap 顯示：換行與連續空白都保留，太長的行仍會自動折行。這是 CSS 而不是把 \n 換成 <br>，所以不用碰 HTML、沒有 XSS 風險。

4概念三：量測「畫面上」的行數

「10 行」算的是畫面上顯示的行數（含自動折行），不是按 Enter 的次數。同一則訊息在寬螢幕可能 6 行、在手機可能 14 行，所以只能渲染後量：

const lineHeight = parseFloat(getComputedStyle(el).lineHeight); // 15px × 1.625 ≈ 24.4px
const maxHeight = lineHeight * 10;
const overflowing = el.scrollHeight > maxHeight + 1;           // +1 容忍小數誤差
  • scrollHeight：內容完整展開的高度（即使被 max-height 擋住也量得到）。
  • 有程式碼區塊時行高不同，就以「10 行文字的高度」為準切，不一定剛好 10 行（已確認）。

寬度變了要重量：ResizeObserver

拖曳分支面板寬度、手機轉向，折行數都會變。ResizeObserver 在元素尺寸改變時通知：

useEffect(() => {
  const ro = new ResizeObserver(measure);
  ro.observe(contentRef.current);
  measure();
  return () => ro.disconnect();
}, [content]);

5概念四：摺疊＋漸層淡出

摺疊時：

style={collapsed ? {
  maxHeight: maxHeight,
  overflow: 'hidden',
  maskImage: 'linear-gradient(to bottom, black 70%, transparent)',
  WebkitMaskImage: 'linear-gradient(to bottom, black 70%, transparent)',
} : undefined}

mask-image 的意思是：遮罩黑色的地方顯示、透明的地方隱藏。漸層從 70% 開始變透明，最後一兩行就淡出，看得出下面還有內容。這跟專案的「浮動控制蓋到文字用 mask 淡出」是同一招（BugB 教學）。

按鈕在被遮罩的內容外面（下方兄弟元素），所以不會跟著淡掉：

<div ref={contentRef} style={...摺疊樣式}>{segments}</div>
{overflowing && (
  <button onClick={toggle} className="mx-auto block ...">
    {expanded ? <ChevronUp /> : <ChevronDown />}
  </button>
)}

6概念五：用 key 讓狀態跟著訊息走

展開狀態放在新元件 UserMessageContent 自己的 state 裡。但 MessageList 的訊息列表現在用 key={index}：切到另一個對話時，第 3 則還是 key 3，React 會沿用同一個元件，上一個對話「第 3 則已展開」的狀態會帶過去。

所以 UserMessageContent 要用訊息 id 當 key：

<UserMessageContent key={msg.id ?? `tmp-${index}`} content={msg.content} />

換對話 → id 不同 → 重新建立 → 回到摺疊。這跟 G3 教學第 5 節「用 key 重置分支 tab 的捲動狀態」是同一個原理。
