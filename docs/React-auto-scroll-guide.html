React 教學筆記

送出訊息才捲到底部,收到訊息不要動

這份文件說明:我們要的行為是什麼、為什麼原本的寫法不夠、最後改了哪幾行,以及它為什麼會有效。

1我們要的四種行為

情境期望由誰負責
自己按送出不管在哪都捲到底新增forceScrollToken
AI 串流中,使用者停在底部跟著內容一起捲原本的 effect
AI 串流中,使用者往上滑不要打斷閱讀原本的 effect
切換對話還原上次閱讀位置skipAutoScrollToken + App 的還原邏輯

關鍵觀察:你原本的程式已經完成了其中三項,缺的只有「自己送出時強制貼底」。所以改動可以很小,不必重寫捲動系統。

2為什麼原本的寫法不夠

原本的 effect 只在「使用者貼在底部」時才捲動(isAtBottomRef.current 為 true)。這很適合串流,但自己送出時有個盲點:

使用者在中間閱讀時按送出,原本的條件會把捲動擋掉

所以送出時我們需要一個「無視位置、強制貼底」的指令,而且它不能依賴 messages 的變化(否則收到訊息也會觸發)。

3解法:用 token 當「只有我會按的按鈕」

App 持有一個數字 sendScrollToken。只有 handleSend 會把它加一,串流與載入對話都不會碰它。MessageList 只要偵測到這個數字變了,就知道「是使用者送出的」。

token 只在送出時改變,所以其他情況一律不會被強制捲動

4到底改了什麼

App.jsx:三處

// ① 新增 state
const [sendScrollToken, setSendScrollToken] = useState(0);

// ② handleSend 裡,放進訊息之後遞增
setMessages(prev => [ ...prev, userMsg, aiPlaceholder ]);
setSendScrollToken(t => t + 1);

// ③ 傳給 MessageList
<MessageList
  skipAutoScrollToken={restoreToken}
  forceScrollToken={sendScrollToken}
/>

MessageList.jsx:兩處

// ① props 加上預設值
forceScrollToken = 0,

// ② 放在 scrollToBottomNow 定義「之後」
const lastForceTokenRef = useRef(forceScrollToken);
useEffect(() => {
  if (forceScrollToken === lastForceTokenRef.current) return;
  lastForceTokenRef.current = forceScrollToken;
  isAtBottomRef.current = true;
  scrollToBottomNow();
}, [forceScrollToken]);

原本的自動捲動 effect、handleScroll、還原閱讀位置的邏輯完全沒動。

5每一行為什麼要這樣寫

寫法原因
lastForceTokenRef 比對元件第一次掛載時 effect 一定會跑一次;比對可以擋掉這次誤觸發
isAtBottomRef.current = true送出後內容會越來越長。先標記「貼底」,後續串流的 chunk 才會被原 effect 接手繼續跟著捲
依賴陣列只放 [forceScrollToken]不放 messages,這樣串流與收訊息都不會觸發它
放在 scrollToBottomNow 之後只是為了好讀(先定義、再使用)。放前面也不會壞,因為 effect 是畫面渲染完才執行,那時函式早就定義好了
用 ref 而非 state 存旗標改 ref 不會造成多餘的重新渲染

6兩個 effect 的執行順序

setMessages 與 setSendScrollToken 在同一個事件中,React 會批次處理,所以兩個 effect 在同一次渲染後依序執行:

B 寫在 A 後面,所以最後以「強制貼底」為準

順序不用太糾結:就算兩個 effect 顛倒,結果也一樣。B 會先把 isAtBottomRef 設成 true 並捲到底,A 看到 true 也只是再捲到底一次,最後都停在底部。

7測試清單與常見問題

測試預期
往上滑到舊訊息,按送出立刻捲到底
串流中停在底部跟著捲
串流中往上滑不動,出現「回到底部」按鈕
切換對話還原上次位置,不被拉到底
送出後沒有完全捲到最底?
Markdown 表格、程式碼高亮會在渲染之後才撐開高度。把新 effect 裡的呼叫改成下面這樣,等瀏覽器排版完再捲: 
requestAnimationFrame(scrollToBottomNow);
順手清理:handleSend 裡有兩次 fetchHistory() 夾著 setMessages,看起來是重複呼叫,留一個即可,與捲動無關。

8這次用到的三個 Hook,白話說明

Hook 就是 React 提供給函式元件的「工具」,名字都以 use 開頭。這次的改動只用到三個,你的專案裡本來就有它們。

三個 Hook 的差別,一張圖記住

① useState:要讓畫面跟著變的資料

const [sendScrollToken, setSendScrollToken] = useState(0);
//     ↑ 目前的值       ↑ 修改它的函式          ↑ 初始值

只能透過 setXxx 修改。一改,React 就會重新執行整個元件,畫面跟著更新。

② useRef:只想「記住」,不想重畫

const isAtBottomRef = useRef(true);
isAtBottomRef.current = false;   // 直接改 .current,畫面不會重畫

它有兩種用途,你的程式碼兩種都有:

  • 記住一個值:isAtBottomRef、lastForceTokenRef、lastAutoScrollSkipToken
  • 指向畫面上的元素:scrollContainerRef,拿來讀寫 scrollTop

③ useEffect:畫面更新後才做的事

useEffect(() => {
  // 這裡的程式碼,在畫面更新完之後執行
}, [forceScrollToken]);   // ← 依賴陣列:只有它變了才執行
依賴陣列寫法什麼時候執行
不寫每次渲染後都執行
[]只在元件第一次出現時執行一次
[a, b]第一次,以及 a 或 b 變了的時候

這次的變數,各自為什麼選這個 Hook

變數Hook原因
sendScrollToken(App)useState要傳給子元件,變了要通知它
isAtBottomuseState決定「回到底部」按鈕顯不顯示,會影響畫面
isAtBottomRefuseRef只是給 effect 判斷用,不需要重畫;而且讀 ref 永遠是最新值
lastForceTokenRefuseRef只是記住上一次的數字,用來擋掉第一次掛載
scrollContainerRefuseRef指向那個可捲動的 div
新增的捲動邏輯useEffect要等新訊息進了 DOM,才能量高度、捲到底
為什麼 isAtBottom 和 isAtBottomRef 要同時存在?
state 負責「讓按鈕顯示或隱藏」(要重畫);ref 負責「在 effect 和事件裡立刻讀到最新答案」(不用重畫)。兩個各司其職,所以 scrollToBottomNow 與 handleScroll 會同時更新它們。

常見疑問 ① 那個 0 是什麼?

0 只是初始值,代表「還沒送出過」。這個數字本身沒有意義,畫面也不會顯示它。它像一個門鈴:每按一次送出就響一次(加一)。換成 Date.now() 也行,只要每次送出時「值不一樣」就好。

那為什麼要用 useState,而不是普通變數?因為 App 要把它傳給 MessageList,而 props 只有在 state 改變、React 重新渲染時才會更新。畫面看不到沒關係,重點是它能通知另一個元件。

常見疑問 ② 該用 useState 還是 useRef?

判斷標準不是「跟不跟捲動有關」,而是「需不需要 React 出手」

更正前面的說法:圖和表格裡提到的「畫面要不要變」,更精確的意思是「React 需不需要重新渲染」。這兩者不完全一樣,下一題會解釋原因。

常見疑問 ③ 捲動不也是改變畫面嗎?

使用者眼睛看到的確實變了,但 React 管的是「畫面上有哪些元素、內容是什麼」(也就是 JSX 的輸出)。捲動只是改瀏覽器對一個現有元素的屬性(scrollTop),元素、文字、結構都沒變,所以 React 完全不需要重畫。

情境JSX 輸出變了嗎誰在處理用什麼
「回到底部」按鈕出現或消失變了ReactuseState
列表多一則訊息變了ReactuseState
捲動位置改變沒變瀏覽器(scrollTop)不需要 state
記錄「現在是否貼在底部」沒變只是程式自己的判斷useRef

常見疑問 ④ 如果沒有子元件呢?

那就不需要 token 了,甚至不需要 state。useState 的本質是「叫 React 重新渲染」;我們用它,是因為 App 和 MessageList 是兩個元件,子元件只能靠 props 變動才知道發生了事。同一個元件裡就沒有這個問題,用 ref 當旗標就夠:

const shouldScrollRef = useRef(false);   // 旗標,用 ref 就夠

// 送出時
shouldScrollRef.current = true;
setMessages(...);

// 渲染完之後
useEffect(() => {
  if (shouldScrollRef.current) {
    scrollToBottom();
    shouldScrollRef.current = false;
  }
}, [messages]);
一句話記住:要讓 React 重畫、或要通知別的元件,用 useState;只是讓程式自己記住東西,用 useRef。

把新的 effect 逐行翻成白話

const lastForceTokenRef = useRef(forceScrollToken);
// 便利貼:先記下「現在的 token」

useEffect(() => {
  if (forceScrollToken === lastForceTokenRef.current) return;
  // 跟便利貼一樣?那就不是送出,什麼都不做

  lastForceTokenRef.current = forceScrollToken;
  // 不一樣!先把便利貼更新成新數字

  isAtBottomRef.current = true;
  // 標記「現在貼在底部」,之後串流才會繼續跟著捲

  scrollToBottomNow();
  // 真的捲到底
}, [forceScrollToken]);
// 只有 token 變了才會進來這個鬧鐘

9一句話總結

不要讓「訊息變動」去決定要不要強制捲動;改讓 App 用一個只有送出時才會加一的 token 通知 MessageList,再搭配原本「貼底才跟隨」的機制,四種行為就各司其職、互不干擾。
