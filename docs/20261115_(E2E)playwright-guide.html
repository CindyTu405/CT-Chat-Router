前端自動測試：讓機器替你點畫面

現在每次改前端，都要你照清單在瀏覽器手動重驗。這份教學說明怎麼把最常重驗的幾項交給機器，以及為什麼要在拆 App.jsx 之前做。

1現況與問題

  • 後端有 9 支 harness 和 CI 保護。前端只有 npm run build，它只能確認「程式碼編得過」，不能確認「按了送出之後畫面是對的」。
  • App.jsx 有 1,139 行。送訊息、重新生成、分支送訊息、分支重新生成是四份很像的程式，各自帶著容易漏掉的保護：
保護沒有它會怎樣
回覆還沒到就切到別的對話 → 停止寫入A 對話的回覆出現在 B 對話裡
額度用完被後端擋下 → 撤掉剛顯示的訊息，文字放回輸入框畫面留著一則其實沒送出的訊息，使用者打的字不見了
第二則訊息要接在上一則 AI 回覆後面（parent_id）對話串斷掉，重新整理後訊息順序錯亂
這些正是重構時最容易弄壞、手動測試最容易漏的地方。所以順序改成：先有測試，再拆 App.jsx。

2概念：測試分三層

層級測什麼這個專案
單元測試單一函式：給輸入，檢查輸出目前沒有
整合測試幾個部分接在一起：真的伺服器加真的資料庫後端 9 支 harness
端對端測試（E2E）從使用者的角度：開瀏覽器、點按鈕、看畫面這次要加的

E2E 最接近真實使用，但最慢也最容易因為小改版而失敗，所以業界的做法是只挑最重要的幾條路徑，不追求全部涵蓋。這次寫六條。

3概念：Playwright

Playwright 是微軟維護的瀏覽器自動化工具，目前業界最常用的 E2E 選擇之一。它會開一個真的 Chromium（沒有視窗，在背景跑），照腳本操作，再檢查畫面。

// 示意，實際程式由 implementer 撰寫
test('送訊息', async ({ page }) => {
  await page.goto('/');
  await page.getByRole('textbox').fill('你好');        // 在輸入框打字
  await page.getByRole('button', { name: '送出' }).click();
  await expect(page.getByText('這是假的回覆')).toBeVisible();   // 檢查畫面
});

它會自動等待：元素還沒出現時會重試幾秒，不用自己寫「等 1 秒」。這是它比舊工具穩定的主要原因。

4概念：假的後端（mock）

測試前端時不啟動真的後端。Playwright 可以攔截瀏覽器發出的請求，直接回一份寫好的假資料：

// 示意
await page.route('**/__api/chat', route => route.fulfill({
  status: 200,
  headers: { 'X-Message-Id': 'ai-1', 'X-User-Message-Id': 'u-1' },
  body: '這是假的回覆',
}));
為什麼這樣做說明
快、穩定不需要資料庫、不需要登入、不呼叫模型，每次結果都一樣
能製造難重現的狀況想測「額度用完」，直接讓假後端回 429；想測「回覆很慢」，讓它晚 1.5 秒才回
能檢查前端送了什麼攔到請求時可以看它的內容，例如 parent_id 對不對
代價：假後端回什麼是我們自己寫的，所以測不到後端的錯，也測不到「前端和後端對格式的理解不一致」。後端的對錯仍由 harness 負責。另外假回應是一次送完，不是真的一段一段串流。

5要寫的六條測試

#操作檢查
1未登入打開網站，按「開始使用」進入聊天畫面
2送兩則訊息訊息與回覆出現、輸入框清空；第二則的 parent_id 是第一則回覆的 id
3送訊息，後端回「額度用完」提示文字正確；訊息被撤掉；文字回到輸入框
4開啟既有對話，按重新生成發出正確的請求；舊回覆被新回覆取代
5點分支高亮，在分支面板送訊息請求帶正確的 branch_id 與 parent_id；回覆出現在面板
6送出後回覆還沒到就切到另一個對話另一個對話裡沒有那則訊息和回覆

第一版只測桌面寬度。手機版、選取文字建立分支、Google／GitHub 登入、OpenRouter 連結先不做，仍照原本的瀏覽器清單人工驗。

6怎麼確認測試本身是有用的

一條永遠通過的測試沒有價值。驗收時會故意把保護拿掉，確認測試會變紅：

  • 刪掉「文字放回輸入框」那一行 → 第 3 條必須失敗。
  • 拿掉「切換對話就不寫入」的判斷 → 第 6 條必須失敗。

確認後還原。這個做法叫變異測試（mutation testing）的手動版：弄壞程式，看測試抓不抓得到。

7怎麼跑

cd frontend
npm run test:e2e              # 跑全部，約幾十秒
npx playwright test --ui      # 開圖形介面，看每一步的畫面（除錯用）

CI 會多一個 e2e job，每次 push 自動跑。失敗時會把當時的畫面截圖和操作紀錄存成附件，可以在 GitHub 的執行頁面下載來看。

第一次在本機跑需要下載 Playwright 的 Chromium（約 170 MB，只下載一次，放在使用者的快取資料夾，不進 repo）。
