首頁互動展示

第一次來的人看不出這個網站在做什麼。這份教學說明怎麼用「假資料」驅動真的聊天元件，做出不花模型額度的互動展示。

1問題

  • 未登入只看到「登入」兩個字和兩顆按鈕，沒有任何產品說明。
  • 產品的重點是「選取回答裡的一段文字，開分支追問」。這個動作用文字很難講清楚，讓人自己做一次最快。
  • 展示不能呼叫模型：OpenRouter 免費額度全帳號每天只有 50 次，不能被路過的人用掉。

2概念：元件只管顯示，資料從外面給

MessageList 和 BranchPanel 自己不呼叫後端。訊息、分支清單、按下按鈕後要做什麼，全部由父層用 props 傳進去。正式介面的父層是 App.jsx，它負責向後端要資料。

所以首頁只要換一個父層（LandingPage），傳入寫死的資料和假的處理函式，同一套元件就會畫出一模一樣的畫面。

App.jsx
向後端要資料
→
MessageList
BranchPanel
←

寫死的範例文章
好處：之後聊天介面改版，首頁展示會自動跟著變，不需要重錄影片或重畫一套假介面。

3概念：用「可選的 prop」擴充共用元件

展示需要兩個正式介面沒有的東西：片語的虛線提示、分支面板底部用說明文字取代輸入框。做法是幫共用元件加上有預設值的 prop，沒傳就和以前完全一樣。

// 示意，實際程式由 implementer 撰寫
function MessageList({ anchorHints = [], onHintClick, ...其他 }) { ... }
function BranchPanel({ footer, ...其他 }) {
  // 有傳 footer 就顯示它，沒傳就顯示原本的輸入框
  {footer ?? <ChatInput ... />}
}
注意：App.jsx 一行都不改。驗收時要回頭檢查正式介面的高亮、建立分支、面板拖曳都沒有變。

4概念：用程式選取文字

正式介面是監聽瀏覽器的 selectionchange 事件，看到使用者選了 AI 回答裡的文字，就顯示「建立分支」按鈕。展示沿用這條路：點虛線片語時，由程式建立一個選取範圍，瀏覽器會發出同一個事件，真的按鈕就會出現。

// 示意
const range = document.createRange();
range.setStartBefore(firstMark);   // 片語的第一段
range.setEndAfter(lastMark);       // 片語的最後一段
const sel = window.getSelection();
sel.removeAllRanges();
sel.addRange(range);               // → 觸發 selectionchange → 出現「建立分支」

片語在文章裡的位置用「字元 offset」記錄（從第幾個字到第幾個字），和正式分支的高亮是同一套機制（見 B1-F8 教學）。資料檔裡用 [[片語]] 標記，載入時去掉標記並算出 offset。

5概念：模擬串流與計時器的清理

預寫的回答用計時器每隔幾十毫秒多顯示幾個字，看起來就像模型在打字。計時器有一個常見的錯誤：元件已經消失或使用者按了「換一篇」，舊的計時器還在跑，把字寫進新的文章裡。

情況要做的事
按「換一篇」先停掉所有計時器，再換資料
離開首頁（按開始使用）useEffect 的清理函式停掉計時器
同一個片語連點兩次已有分支就直接開啟，不再建立第二條

6概念：自動播放是一串可以取消的步驟

等 1.2 秒
→
假游標移到片語
→
選取片語
→
移到「建立分支」
按下
→
分支逐字回答

假游標只是一個絕對定位的圖示，用 CSS transition 移動。每一步之間用計時器銜接。使用者只要按下滑鼠、鍵盤、滾輪或觸控，就把「已取消」的旗標設起來並清掉計時器，之後不再自動操作。

無障礙：系統設定了「減少動態效果」（prefers-reduced-motion）的人不播放，直接顯示可以操作的畫面。
手機不一樣：手機的分支面板是滿版覆蓋。自動打開會蓋住整個首頁，所以手機只播到「建立分支」按鈕出現，由使用者自己按。

7概念：未登入時在首頁與登入頁之間切換

AuthGate 原本是：檢查中 → 空白、未登入 → 登入頁、已登入 → 聊天。現在未登入時多一個狀態 view，值是 landing 或 login。不用路由套件，也不改網址。

例外：登入失敗被後端導回時網址帶有 auth_error，這時要直接顯示登入頁，使用者才看得到錯誤訊息。
