沒有路由，也能按「上一頁」

用 History API（pushState／popstate）讓訪客從聊天回到首頁。

1問題

訪客按「開始使用」後，POST /auth/guest 寫入 cookie，/auth/me 開始回傳訪客資料。AuthGate 的規則是「有 user 就顯示 <App>」，首頁只在 user === null 時出現，所以：

  • 側欄沒有任何回首頁的入口（訪客也沒有登出）。
  • 網址一直是 /，瀏覽器的歷史紀錄裡沒有「首頁」和「聊天」兩筆，按「上一頁」會直接離開網站。
  • 重新整理還是聊天畫面（cookie 還在）。

登入的使用者不受影響，也不需要回首頁（使用者決定，2026-11-18）。

2概念：瀏覽器的歷史堆疊

每個分頁都有一串「歷史紀錄」（session history），「上一頁／下一頁」就是在這串紀錄裡移動。平常是換網址時瀏覽器自動加一筆。單頁應用（SPA）不換頁，所以要自己用 JavaScript 加：

API做什麼會不會觸發 popstate
history.pushState(state, '', url)在目前位置後面新增一筆紀錄並移過去（後面原本的「下一頁」紀錄會被丟掉）不會
history.replaceState(state, '', url)改寫目前這一筆紀錄，不新增不會
history.back()／forward()等於按「上一頁」／「下一頁」會（非同步）
history.state讀目前這筆紀錄存的 state 物件（重新整理後還在）—

state 是我們自己定的小物件，每筆紀錄各存一份。使用者按上一頁／下一頁時，瀏覽器觸發 popstate 事件，event.state 就是「移到的那一筆」的 state。我們看它決定畫面：

紀錄 1
{ctView:'landing'}
首頁
→
紀錄 2
{ctView:'app'}
聊天

網址三個參數的第三個不傳（或傳目前網址），所以網址列一直是 /，只有 state 不同。不需要 react-router。

重點：pushState 只是「記一筆」，不會改畫面；popstate 只是「通知你移到哪一筆」，畫面也要自己改。History API 和 React state 是兩件事，要自己對齊。

3為什麼這樣設計

  • 不加路由套件：整個 app 只有「首頁／聊天」這一個切換，引入 react-router 會牽動 AuthGate、OAuth 回呼網址和 nginx 設定，成本遠大於兩個 API 呼叫。
  • 網址不變：OAuth 回呼、auth_error、openrouter 參數都在 / 上處理，不改網址就不會影響它們。
  • App 不卸載，只隱藏：回首頁時 <App> 留著（hidden），按「下一頁」或「開始使用」回來時，開著的對話、捲動位置、串流都還在。

4程式草稿

以下是給 implementer 的方向，實際寫法以 commit 為準。

① AuthGate：新增 showLanding，只對訪客生效

// frontend/src/components/AuthGate.jsx
const [showLanding, setShowLanding] = useState(false);

// 訪客進到聊天時，確保歷史裡是「首頁 → 聊天」兩筆
useEffect(() => {
  if (!user?.is_guest) return;
  const cur = history.state?.ctView;
  if (cur === 'landing') {
    setShowLanding(true);              // 在首頁那筆上重新整理：留在首頁
  } else if (cur !== 'app') {
    history.replaceState({ ctView: 'landing' }, '');  // 第一次進來：目前這筆改成首頁
    history.pushState({ ctView: 'app' }, '');         // 再疊一筆聊天
  }
}, [user?.is_guest]);

// 上一頁／下一頁
useEffect(() => {
  const onPop = (e) => {
    if (!user?.is_guest) return;       // 登入的使用者忽略
    setShowLanding(e.state?.ctView === 'landing');
    setView('landing');                // 順便關掉登入覆蓋層
  };
  window.addEventListener('popstate', onPop);
  return () => window.removeEventListener('popstate', onPop);
}, [user?.is_guest]);

② 「開始使用」：已經是訪客就不再發試用請求

const startGuest = async () => {
  if (user?.is_guest) {                // 從聊天回到首頁後再按
    history.pushState({ ctView: 'app' }, '');
    setShowLanding(false);
    return;                            // 不打 /auth/guest，不扣試用名額
  }
  // ……原本的 POST /auth/guest 流程
};

第一次按「開始使用」時 user 還是 null，走原本流程；refreshUser() 拿到訪客後，①的 effect 會補上兩筆紀錄。

③ 畫面：首頁蓋在 App 上面，App 只隱藏

<div className={showLanding ? 'hidden' : undefined}>
  <App ... onGoHome={() => history.back()} />
</div>
{showLanding && <LandingPage onStart={startGuest} onLogin={() => setView('login')} />}

④ 側欄「回首頁」：只給訪客，放在「隱私權說明」左邊

// frontend/src/components/Sidebar.jsx（帳號區底部那一列）
<div className="flex gap-3 pl-7">
  {user?.is_guest && (
    <button type="button" onClick={onGoHome} className="text-xs text-gray-500 ... underline">回首頁</button>
  )}
  <a href="/privacy.html" ...>隱私權說明</a>
</div>

按鈕呼叫 history.back() 而不是直接 setShowLanding(true)：這樣按完「回首頁」，瀏覽器的「下一頁」也能回到聊天，兩種操作走同一條路（popstate）。①保證了聊天那筆前面一定是首頁那筆。

6練習

  1. 在 DevTools Console 執行 history.pushState({a:1}, '')，再按瀏覽器上一頁。畫面有變嗎？網址有變嗎？
  2. 加上 addEventListener('popstate', e => console.log(e.state))，按上一頁、下一頁，看印出什麼。
  3. 為什麼①要先 replaceState 再 pushState，而不是只 pushState 一次？（提示：重新整理後直接進聊天的訪客，前面是什麼紀錄？）
  4. 如果「回首頁」直接寫 setShowLanding(true)，按完後瀏覽器的「下一頁」還能用嗎？
