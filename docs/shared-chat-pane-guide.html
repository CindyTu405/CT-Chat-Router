一個組件，兩種樣子

主對話和分支面板共用同一套訊息列表與輸入框：variant、可選 props、absolute 定位、用 key 重置狀態。

1現在的問題：同一件事寫了兩遍

主對話和分支面板長得很像，但程式碼是兩份各自獨立的複製品：

功能主對話分支面板
Markdown 渲染（程式碼、表格、連結）MessageList.jsx 的 buildMarkdownComponentsBranchPanel.jsx 內又寫一份（262–324 行）
訊息氣泡＋頭像MessageList.jsx 390–447 行BranchPanel.jsx 240–331 行
捲動貼底判斷＋「回到底部」按鈕只有 scrollIntoView({ behavior: 'smooth' })，沒有貼底判斷、沒有按鈕
輸入框ChatInput.jsx（含模型選單）自己一個 textarea，沒有模型選單
模型標籤、送出時間有沒有

後果：之後的 G4（模型資訊）、G6（重傳）、G8（複製）、G9（換行摺疊）每一項都要做兩遍、驗兩遍，而且兩邊很容易慢慢長得不一樣。

G3 的 bug 也是這樣來的：「回到底部」按鈕只存在主對話，但它用 position: fixed 釘在整個視窗右下角，所以分支面板一打開，按鈕就浮在分支面板上（見第 4 節）。

2概念一：variant —— 同一個模具，不同設定

做法不是「複製一份再改」，而是讓同一個組件吃一個 variant prop，差異集中寫在一張設定表裡：

// 差異集中在一個物件，不要散落成一堆 if
const VARIANTS = {
  main: {
    showAvatar: true,
    textSize: 'text-[15px]',
    bubblePadding: 'px-5 py-3.5',
  },
  branch: {
    showAvatar: false,
    textSize: 'text-[13px]',
    bubblePadding: 'px-3 py-2',
  },
};

function MessageList({ variant = 'main', ...props }) {
  const v = VARIANTS[variant];
  ...
  {v.showAvatar && <Avatar role={msg.role} />}
  <div className={`${v.bubblePadding} ${v.textSize} ...`}>
}

使用的地方只差一個字：

// App.jsx（主對話）
<MessageList variant="main" messages={messages} ... />

// BranchPanel.jsx（分支）
<MessageList variant="branch" messages={activeBranch.messages} ... />
為什麼用設定表而不是到處寫 variant === 'branch' ? … : …：想知道「分支跟主對話差在哪」，只要看 VARIANTS 一個地方。要調分支的字級，也只改一行。

default = 'main' 的意義：App.jsx 現在的呼叫不用改就維持原樣，第一步的重構才能做到「主對話畫面完全不變」。

3概念二：可選 props —— 有傳才有功能

有些功能只屬於主對話：選取文字建立分支、錨點高亮、閱讀位置還原。這些不用寫進 variant，而是用「有傳這個 prop 才啟用」的方式：

prop主對話傳分支不傳 → 結果
onCreateBranch✅選取文字不出現「建立分支」按鈕（現有程式碼第 172 行已經這樣判斷）
branchList✅預設 []，不會有高亮
scrollContainerRef、skipAutoScrollToken✅改用組件內部的 ref，不做閱讀位置還原
emptyState（新增）建議提示卡片「尚未開啟分支」或「這條分支還沒有訊息」

分辨原則：「長得不一樣」放 variant；「有沒有這個功能」用可選 prop。

4概念三：fixed vs absolute —— G3 的根因

position 決定元素「以誰為座標原點」：

寫法座標原點「回到底部」按鈕的結果
fixed bottom-24 right-8（現在）整個瀏覽器視窗永遠在視窗右下角。分支面板開著時，視窗右下角就是分支面板 → 按鈕跑到分支上
absolute bottom-4 right-4（改成）最近一個 relative 的祖先釘在「自己那一區」的右下角，主對話的在主對話裡、分支的在分支裡
陷阱：不能直接把 absolute 放在捲動容器（overflow-y-auto）裡面，否則按鈕會跟著內容一起被捲走。要在外面多包一層 relative，按鈕放在捲動容器的旁邊：
<div className="relative flex-1 min-h-0 flex flex-col">   ← 座標原點，不捲動
  <div className="flex-1 overflow-y-auto" onScroll={...}>  ← 捲動的是這層
    {訊息們}
  </div>
  {!isAtBottom && (
    <button className="absolute bottom-4 right-4 ...">     ← 兄弟，不在捲動層內
  )}
</div>

min-h-0：flex 子元素預設最小高度是內容高度，不加的話外層會被訊息撐高、捲軸消失。

5概念四：用 key 讓每個分支 tab 有自己的捲動狀態

分支面板一次只顯示一個 tab 的訊息。MessageList 內部記著 isAtBottom（使用者是不是貼在底部）。如果切換 tab 時沿用同一個組件實例，上一個 tab「捲到一半」的狀態會帶到下一個 tab。

<MessageList key={activeBranchId} variant="branch" ... />

React 看到 key 變了，會把舊的組件整個丟掉、重新建一個：內部 state 全部回到初始值（isAtBottom = true），所以切 tab 時自然捲到底，跟現在的行為一樣。

切到分支 B
key: A → B
→
卸載 A 的 MessageList
→
掛載新的
isAtBottom = true
→
訊息載入
自動貼底

6輸入框：程式碼共用，畫面仍是兩個

主對話底部、分支面板底部各有一個輸入框，各自送到各自的對話。兩者都用 ChatInput 產生，也都有模型選單。

// BranchPanel.jsx
<ChatInput
  variant="branch"
  input={activeBranch.input}
  setInput={(text) => onInputChange(activeBranch.id, text)}
  isLoading={activeBranch.isLoading}
  onSend={() => onSend(activeBranch.id)}
  model={model} setModel={setModel} ...   ← 跟主對話是同一個 state
/>

model 只有一個（App.jsx 第 27 行），兩個選單綁同一個值：在分支換模型，主對話的選單也跟著變。這就是現在的行為（分支送出本來就用這個 model），只是多了一個可以改它的地方。

7分兩步做

步驟改什麼畫面變化
G3-1 抽取MessageList、ChatInput 加 variant（預設 main）與 emptyState；「回到底部」改 absolute＋外層 relative。不動 BranchPanel。主對話只有「回到底部」按鈕位置改為主對話區右下角，其他不變
G3-2 套用BranchPanel 改用 <MessageList variant="branch" key={activeBranchId}> 與 <ChatInput variant="branch">，刪掉它自己的 Markdown／氣泡／textarea分支：無頭像、有模型選單、有「回到底部」、貼底自動捲

先做 G3-1、確認主對話沒壞，再做 G3-2。出問題時能直接看出是「抽取壞了」還是「套用壞了」。
