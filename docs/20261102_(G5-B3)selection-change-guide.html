保住選取、跟著選取

為什麼選完字反白馬上消失、為什麼手機沒有「建立分支」按鈕；React 元件身分、selectionchange、防抖。

1兩個症狀，同一塊程式碼

編號症狀根因
G5（電腦）選完字放開滑鼠，反白馬上消失；shift+方向鍵無法再調整按鈕出現時整段訊息的 DOM 被 React 拆掉重建，選取跟著不見（第 2 節）
B3（手機）長按選字後沒有「建立分支」按鈕只監聽滑鼠的 mouseup，手指選字不會觸發（第 3 節）

兩者都在 MessageList.jsx 的「選取 → 建立分支」流程，所以合併成一個任務修。

2概念一：React 用「元件型別」決定要不要重建 DOM

React 每次重新渲染時，會比對新舊兩棵樹。同一個位置上：

  • 型別一樣（同一個函式、同一個標籤）→ 保留原本的 DOM，只更新有變的屬性。
  • 型別不一樣 → 把舊的 DOM 整個拆掉，重新建一個。

現在的程式碼每次渲染都呼叫一次 buildMarkdownComponents(...)：

// MessageList.jsx 現況（簡化）
<ReactMarkdown
  components={buildMarkdownComponents(msg.role, branchById, onOpenBranch)}
>

const buildMarkdownComponents = (role, ...) => ({
  p: ({ children }) => <p className="...">{children}</p>,   ← 每次呼叫都產生一個「新的」函式
  code: (...) => ...,
  ...
});

p 雖然長得一樣，但每次都是新的函式，對 React 來說就是不同型別的元件。於是：

放開滑鼠
→
setBranchSel
（要顯示按鈕）
→
MessageList 重新渲染
→
p / code 是新函式
→ DOM 全部重建
→
選取指向的舊文字節點
消失 → 反白不見

修法：讓這些元件函式只建立一次，之後每次渲染都是同一個身分。

// 建立一次：依 role 各一份，用 useMemo 固定下來
const assistantComponents = useMemo(
  () => buildMarkdownComponents('assistant', branchByIdRef, onOpenBranchRef),
  []
);

高亮 mark 需要的 branchById、onOpenBranch 會隨資料改變，不能寫死在建立時，所以改用 ref 傳進去：ref 物件本身不變（元件身分不變），點擊時才讀 ref.current 拿最新值。

順便的好處：串流時每來一段文字也會重新渲染。元件身分固定後，React 只更新有變的文字節點，不再整段重建，捲動和效能都比較穩。

3概念二：selectionchange —— 不管用什麼方式選，都會通知

現在只在 AI 泡泡的 onMouseUp 檢查選取。這只涵蓋「滑鼠拖曳」：

選取方式mouseupselectionchange
電腦：滑鼠拖曳✅✅
電腦：shift＋方向鍵調整❌✅
手機：長按選字❌✅
手機：拖控制棒調整❌✅

selectionchange 掛在 document 上，選取範圍只要有變就觸發：

useEffect(() => {
  const onSelectionChange = () => {
    clearTimeout(timer);
    timer = setTimeout(updateBranchButton, 300);   // 防抖：停手 0.3 秒才更新
  };
  document.addEventListener('selectionchange', onSelectionChange);
  return () => { ...移除監聽、清計時器... };
}, []);

updateBranchButton 做的事跟原本 mouseup 版一樣：確認選取完全落在同一則 AI 泡泡內、算 source offset（F7 的 selectionOffsets）、決定按鈕位置。差別只是「誰來呼叫它」。

要知道選取落在哪一則訊息：從選取的節點往上找 data-message-id（F1b 已經掛在每則訊息上）。

4概念三：防抖（debounce）

拖控制棒或按住 shift＋方向鍵時，selectionchange 一秒會觸發幾十次。每次都重算位置、重新渲染，按鈕會一直閃。

防抖的意思是：每次事件都把計時器重設，只有「停下來 300ms 沒有新事件」才真正執行。

變 變 變 變
→
停手 300ms
→
更新按鈕一次

「隱藏」也走同一個防抖。這剛好解決一個手機陷阱：手指點按鈕時，瀏覽器會先清掉選取（觸發 selectionchange），如果立刻隱藏按鈕，點擊就落空了。有 300ms 緩衝，點擊會在按鈕消失前送達；而按鈕要用的文字和 offset 在顯示時就已存進 state，選取被清掉也不影響。

另外在按鈕上加 onMouseDown={e => e.preventDefault()}：電腦版點按鈕時不會先把選取清掉。只擋按鈕自己，不影響其他地方的 Ctrl+C／右鍵複製。

5按鈕放哪裡：電腦上方、手機下方

手機選字後，系統會在選取範圍上方跳出原生工具列（複製、全選…），我們的按鈕放上方會被蓋住，所以：

位置理由
電腦（≥ 768px）選取範圍上方（現況）沒有原生工具列
手機（< 768px）選取範圍下方，再往下讓開控制棒避開原生工具列
const rect = range.getBoundingClientRect();
const isMobile = window.innerWidth < 768;
const y = isMobile
  ? rect.bottom + MOBILE_BUTTON_OFFSET     // 往下，避開控制棒（可調）
  : rect.top - 8;                          // 往上（現況）
