CSS 漸層遮罩與 hover 狀態

為什麼標題要「淡出」而不是「裁切」？為什麼 ⋯ 按鈕一滑過去，對話列的底色就消失？兩個問題背後的 CSS 觀念都在這篇。

0. 先看結果

側欄的每一列有三個元素：左邊的圖示、中間的標題、右邊的 ⋯ 按鈕。這次要解決三件事：

  • 標題太長時，右端不要被生硬切掉，也不要蓋到 ⋯ 按鈕。
  • ⋯ 按鈕只有在滑鼠 hover 到這一列時才出現。
  • 滑鼠移到 ⋯ 上時，這一列的底色不能消失；點進去的那一列，底色要保持。

1. 文字溢出：overflow 三兄弟

單行文字太長時，瀏覽器預設會讓文字超出容器。要控制它，通常會搭配三個屬性：

white-space: nowrap;     /* 不換行，維持單行 */
overflow: hidden;        /* 超出容器的部分不顯示 */
text-overflow: ellipsis; /* 被裁掉的地方補上 … （我們這次沒用）*/

前兩個組合起來就是「硬切」：文字到邊界就停。text-overflow: ellipsis 會補上省略號，但我們要的是「不要省略號」，所以只用前兩個。

為什麼硬切不夠好？

硬切的問題是邊界很生硬。標題的最後一個字可能剛好切一半，看起來像 bug。而且如果右邊還有 ⋯ 按鈕，文字可能直接鑽到按鈕底下。

解法：mask-image 漸層遮罩

mask-image 是「遮罩」：用一張圖（這裡是漸層）決定元素每個位置要顯示多少。黑色＝完全顯示，透明＝完全隱藏，中間的灰階＝半透明。

mask-image: linear-gradient(
  to right,
  #000 calc(100% - 3rem),   /* 從左到右，到倒數 3rem 之前都完全顯示 */
  transparent 100%          /* 最右邊完全透明 */
);

這一行的意思是：「最後 3rem 的寬度內，從不透明漸變成透明」。文字不會被硬切，而是慢慢淡出。

為什麼用 calc(100% - 3rem)？
100% 是元素的整個寬度；3rem 是固定長度（相對於根字體大小）。兩者相減就是「右邊留 3rem 的漸層區」。這樣不管側欄寬度怎麼拖，漸層長度都固定，不會因為寬度變化而失真。

為什麼要寫兩行（-webkit- 前綴）？

較舊的 Safari／Chrome 仍需要 -webkit-mask-image。現在我們同時寫兩行，相容性比較好。

調整漸層長度（這次的踩坑）

第一次我用 2.5rem，發現漸層還是沒有蓋到 ⋯ 按鈕右側，所以改成 3rem。漸層長度必須 ≥ 按鈕所在區域的寬度，而且它的右邊界要和文字的右邊界對齊。這次同時把按鈕的 pr-10 改成 pr-2，讓文字可以延伸到按鈕右側，漸層才有意義。

常見誤解
以為「文字被遮住」是 padding-right 的功勞。其實 padding-right 只是讓文字不要進入那段空間；如果你要文字「延伸進去並淡出」，就要把 padding 縮小，再用遮罩處理右端。

2. hover 的範圍：為什麼滑到 ⋯ 底色會消失？

原本的結構是這樣：

<div class="group relative">
  <button class="... hover:bg-white/80">   <!-- 底色綁在這裡 -->
    圖示 + 標題
  </button>
  <div class="absolute ...">                  <!-- ⋯ 按鈕，不在 button 裡面 -->
    <button>⋯</button>
  </div>
</div>

關鍵：⋯ 不是 button 的子元素。滑鼠移到 ⋯ 上，就等於離開了 button，所以 button:hover 就失效，底色跟著消失。

解法：把 hover 底色放到共同的父層

⋯ 和 button 共同的父層是外層的 div.group。只要滑鼠在這個 div 裡面（包含 ⋯），它的 hover 就成立。

<div class="group relative rounded-xl hover:bg-white/80">   <!-- 底色移到這裡 -->
  <button class="... cursor-pointer">
    圖示 + 標題
  </button>
  <div class="absolute ... group-hover:opacity-100">
    <button>⋯</button>
  </div>
</div>
原則
hover 的範圍 = 元素自己 + 所有子元素。想讓「列」的 hover 包含整列（包含按鈕），就把 hover 掛在包住整列的最外層元素上，而不是其中一個子元素上。

group 與 group-hover：控制子元素的顯示

Tailwind 的 group 會把父元素標記為「群組」，子元素就能用 group-hover: 響應父元素的 hover。這裡 ⋯ 按鈕預設 opacity-0，hover 到列時才變成 opacity-100。

class="opacity-0 group-hover:opacity-100 transition-opacity"

為什麼用 opacity 而不是 display: none？因為 opacity 可以搭配 transition 做淡入淡出；而且按鈕仍在版面中，不會讓標題寬度跳動。

為什麼去掉 group-focus-within？

我們原本有 group-focus-within:opacity-100，意思是「列裡面有元素拿到焦點，⋯ 就顯示」。問題是：點進對話時，按鈕會拿到焦點，⋯ 就一直顯示，不符合「只有 hover 才出現」的需求。所以這次把 focus 條件拿掉。

無障礙注意
拿掉 focus 顯示後，鍵盤使用者按 Tab 到 ⋯ 時看不到它。如果之後要照顧鍵盤使用者，可以只在「鍵盤焦點」時顯示（:focus-visible），而不是任何焦點。

3. 「目前開啟中」的狀態：不能只靠 hover

hover 是暫時的：滑鼠一離開就消失。但使用者點進一個對話後，希望這一列「被選中」的底色留著。這是狀態（state）的問題，不是 CSS hover 能解的。

做法：用 JavaScript 比對 id，套用 class

// Sidebar.jsx（父元件）
<ChatRow activeChatId={messages[0]?.id ?? null} ... />

// ChatRow（子元件）
const isActive = chat.id === activeChatId;
<div className={`group relative rounded-xl transition-all ${
  isActive ? 'bg-white/80 shadow-sm'
           : 'hover:bg-white/80 hover:shadow-sm'
}`}>
三個重點
  • 狀態放在父層：「哪一個對話開啟中」是 App 的事，由 App 傳下去（props）。
  • 子元件只負責顯示：ChatRow 不需要知道其他列的狀態，只要比對「我是不是 active」。
  • active 與 hover 互斥：active 時不再套 hover 樣式，避免兩者疊加難以分辨。

為什麼用 messages[0]?.id？

目前的對話 id 是「根節點（root）」的 id，也就是 messages 陣列的第一則訊息。側欄每一列的 chat.id 也是根節點 id，所以兩者可以直接比對。

?. 是「可選串接」：如果 messages 是空的（新對話），messages[0] 是 undefined，整個運算式變成 undefined，不會報錯；?? null 再把它轉成 null。

動態 class：三元運算子

模板字串裡的 ${isActive ? A : B} 會依條件選擇一組 class。這是 React 裡最常見的「依狀態換樣式」寫法。
