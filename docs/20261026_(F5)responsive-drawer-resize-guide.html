響應式抽屜與可拖曳寬度

同一個側欄，手機是全屏抽屜，桌面是可以拖寬的並排欄位。這篇說明怎麼用同一套 class 達成，以及這次踩到的三個坑：class 衝突、inline style 與 class 的優先序、把手的定位父層。

0. 目標行為

手機（< 768px）桌面（≥ 768px）
左側欄全屏抽屜，左上 X 關閉並排，可拖寬（12%–30%）
右側分支面板全屏，右上 X 關閉並排，可拖寬（20%–50%）
拖曳把手隱藏貼在欄位邊緣

1. 響應式前綴：md: 是什麼

Tailwind 的斷點前綴讓同一個 class 只在某個寬度以上生效：

class="fixed inset-0 w-full md:relative md:w-auto"
//    ↑ 所有寬度都生效          ↑ 只在 ≥ 768px 生效

寫法的規則是手機優先：沒有前綴的是預設（手機），md: 覆蓋桌面。所以手機的全屏覆蓋寫成無前綴，桌面再用 md: 改回並排。

2. 定位（position）：fixed、relative、absolute 各自的角色

值位置相對於是否佔版面這裡的用途
static正常文件流是預設（桌面並排的欄位）
relative自己原本的位置是成為子元素的定位父層
absolute最近的 relative／absolute／fixed 祖先否拖曳把手、手機的 X 按鈕
fixed視窗（viewport）否手機抽屜，蓋住整個畫面
關鍵規則
子元素的 absolute 要貼在欄位邊緣，欄位本身必須是 relative（或 absolute／fixed）。如果欄位是 static，子元素會跑到更外層的定位祖先，看起來就像「跑掉了」。

3. 踩坑一：同一個元素上的 class 衝突

這次的問題是側欄 class 字串裡同時出現：

className="... md:static ... md:relative ..."

兩個都是 md: 斷點，CSS 裡後定義的規則勝出。Tailwind 產生的 CSS 順序是 md:relative 先、md:static 後，所以結果是 static。拖曳把手因此失去定位父層，跑到頁面右上角。

判斷方式
同一個屬性（position、width、display）只能有一個生效的值。class 字串裡不要同時放兩個互斥的值。要確認實際生效的值，用瀏覽器的 getComputedStyle(el).position 查，不要只看 class 字串。

修正

// 修正前：md:static 覆蓋 md:relative
className="fixed inset-0 z-40 w-full md:static md:z-auto ... md:relative"

// 修正後：只保留 md:relative
className="fixed inset-0 z-40 w-full md:z-auto ... md:relative"

4. 踩坑二：flex 沒開，flex-col 與 mt-auto 全部失效

側欄的底部使用者區塊要貼齊底部，寫了 mt-auto，但它沒有貼底。原因是開啟狀態的 class 少了 flex：

// 錯：只有 flex-col，沒有 flex，所以 display 是 block
className="fixed inset-0 ... flex-col"

// 對：flex 讓 flex-col 生效，mt-auto 才會把底部推到底
className="flex fixed inset-0 ... flex-col"
原則
flex-col、flex-1、mt-auto 都依賴父層是 flex 容器。修改 class 時先確認 display 是 flex。

這個狀態也說明了為什麼要區分「開啟」與「收起」兩組 class：收起時用 hidden md:flex md:w-0，開啟時用 flex fixed ...，兩組都要明確寫出 display。

5. 踩坑三：inline style 與 class 的優先序

桌面寬度是百分比，用 inline style 寫：

style={{ width: `${sidebarPct}%` }}

inline style 的優先序高於 class（除非 class 用 !important）。所以手機要的 w-full，會被桌面的 inline 百分比蓋掉。

解法：讓 inline style 只在桌面生效
用 JavaScript 的 matchMedia 判斷目前是否為桌面，只在桌面才設 inline 寬度：
const [isDesktop, setIsDesktop] = useState(() =>
  window.matchMedia('(min-width: 768px)').matches
);
useEffect(() => {
  const mq = window.matchMedia('(min-width: 768px)');
  const onChange = (e) => setIsDesktop(e.matches);
  mq.addEventListener('change', onChange);
  return () => mq.removeEventListener('change', onChange);
}, []);

style={isDesktop ? { width: `${sidebarPct}%` } : undefined}

為什麼不用 CSS 解決？因為 inline style 無法被 class 的斷點覆蓋。只要寬度是由 JavaScript 算出來的，就得由 JavaScript 決定什麼時候套用。

6. 拖曳把手：如何實作

示範：側欄右緣的把手
側欄 25%
主畫面

(1) 把手貼在邊緣

<div class="absolute top-0 right-0 h-full w-1.5 -mr-[3px] cursor-col-resize">
  • absolute + top-0 right-0 h-full：貼在父層右上到右下。
  • -mr-[3px]：把把手往右推半個寬度，讓它跨在邊界線上，不會蓋住內容。
  • 父層（側欄）必須是 relative，見第 2 節。

(2) pointer 事件：按下、移動、放開

// 按下：只在把手上觸發，記錄正在拖曳
onPointerDown={(e) => { e.preventDefault(); setIsResizing(true); }}

// 移動與放開：掛在 window 上，拖到欄位外也能持續追蹤
useEffect(() => {
  if (!isResizing) return;
  const onMove = (e) => {
    const percent = (e.clientX / window.innerWidth) * 100;   // 側欄：游標位置 ÷ 視窗寬
    setSidebarPct(clamp(percent, 12, 30));
  };
  const onUp = () => setIsResizing(false);
  window.addEventListener('pointermove', onMove);
  window.addEventListener('pointerup', onUp);
  window.addEventListener('pointercancel', onUp);
  return () => { /* 移除三個監聽 */ };
}, [isResizing]);

(3) 為什麼監聽掛在 window 上？

把手只有 6px 寬，使用者拖得很快時游標很容易離開把手。如果 pointermove 掛在把手上，游標一離開就會斷掉。掛在 window 上，只要按鈕沒放開，移動都會被接收。

(4) 寬度換算成百分比

寬度存成視窗寬度的百分比（12–30%），而不是像素。視窗縮放時比例不變，不會因為固定像素而超出畫面。側欄與分支面板的換算方向不同：

欄位位置寬度公式
左側欄貼左邊游標 X ÷ 視窗寬 × 100
右側分支面板貼右邊(視窗寬 − 游標 X) ÷ 視窗寬 × 100

(5) 拖曳時的副作用

  • 鎖住文字選取：拖曳時設 document.body.style.userSelect = 'none'，避免拖過的文字被反白。
  • 游標樣式：設 cursor = 'col-resize'，整頁都顯示水平拖曳游標。
  • 關閉過渡動畫：拖曳時不套用 transition-[width]，否則寬度會有延遲感。
  • 清理：effect 的清理函式還原 userSelect 與 cursor，並移除三個監聽。

7. 持久化

寬度寫入 localStorage，重新整理後保留：

const [sidebarPct, setSidebarPct] = useState(() => {
  const num = parseFloat(localStorage.getItem(KEY));
  return Number.isFinite(num) ? clamp(num, 12, 30) : 20;   // 讀取時也要夾住範圍
});
useEffect(() => { localStorage.setItem(KEY, String(sidebarPct)); }, [sidebarPct]);
為什麼讀取時也要 clamp？
localStorage 的值可能是舊版本寫入的，或被手動修改。讀取時夾住範圍，才不會讓欄位寬度跑出合理區間。
